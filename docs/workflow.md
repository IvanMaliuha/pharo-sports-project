# Робочий процес команди

## Організація роботи

Команда розділила проєкт на три частини: проєктування класів і модульні тести, робота з колекцією спортсменів, збереження та завантаження даних.

Для спільної роботи використовується публічний GitHub-репозиторій. Кожен учасник працює у власній гілці, зберігає зміни окремими комітами та передає завершену роботу на перевірку через Pull Request.

## Труднощі

Після виконання проєкту додати реальні приклади труднощів, з якими зіткнулася команда. Для кожної труднощі описати:
- що саме не працювало;
- як вдалося знайти причину;
- яке рішення було застосовано;
- як перевірили, що проблема зникла.

## Переваги командної роботи

Після завершення проєкту описати, як розподіл роботи допоміг виконувати завдання паралельно, як GitHub зберігав історію змін і як Pull Request допомагав перевіряти сумісність частин.

## Висновки

Після завершення роботи підсумувати, чого команда навчилася щодо об’єктно-орієнтованого програмування у Pharo, модульного тестування та спільної розробки з Git і GitHub.
